### Notes on PR 1a (decisions where the design was silent; a reviewer can reverse any of them)

- **Where the code lives.** `incubating/azure-waf-review/`, not `plugins/azure-waf-review/`. `scripts/validate-skills.mjs` fails on a `plugins/*/skills/*` folder without `SKILL.md` and on a `plugins/*` folder that is not in the marketplace manifest, and `test/prompt-examples.test.mjs` finds skills by `SKILL.md` and agents by `agents/*.md`; the example prompts come in PR 3 and 4, and a marketplace entry would list an unfinished plugin the moment this is merged. The layout mirrors the future skill folder (`scripts/`, `catalog/`, `test/`), so PR 3 is a `git mv` plus `SKILL.md`, `references/` and the manifest. Alternatives considered: `plugins/azure-waf-review/engine/` (fails `validate-skills` without a marketplace entry); a stub `SKILL.md` and `prompts.md` (false examples, refused).
- **No real tenant in 1a.** `plan` and `collect` run only with `--fixtures`; without it they exit 1 and name the consent file of PR 1b. The production transport (`az` through `execFile`, constant arguments, environment allowlist, a body file for Resource Graph) exists and is tested against a stub executable, never against `az`.
- **Extension points for 1b.** `waf.mjs` has a command table (`consent`, `cap-check`, `render`, `reverify`, `purge` answer "not in this build"); `catalog/az-read.json` already lists the consent vectors; `map.json` records, per check, the finding, the evidence ids, the query hashes and the sealed part hashes that `cap-check` and `reverify` compare; the manifest keeps the part hashes, the catalog hash and the query hashes.
- **Scope and `pass`.** The query scope is the readable subscriptions that are also under the management group. If any subscription under the group is not readable or not Enabled (Disabled, Warned, PastDue), or the readable count differs from the typed count, the scope is incomplete: a clean result (`pass` or `not-applicable`) becomes `not-verified:scope-incomplete`, and a `fail` stays `fail` with `scopeComplete: false` recorded. A scope problem never falls back to the questionnaire.
- **Questionnaire fallback** only for `no-permission`, `no-api`, `timeout`, `error` and `truncated`; with an answers file present, an unanswered item is `not-verified:unanswered`, without it `needs-questionnaire`.
- **Inconsistent counts.** Violations with nothing evaluated is `not-verified:error` (class `inconsistent`), never `fail` and never `pass`. The `evaluated` query must end in `summarize n=count()`.
- **`rest-get`.** One GET per readable subscription; the one shipped check (`OE-LOCK-001`) is a violation when `value` is empty (`violationWhen: empty-value`); a `nextLink` ends the check as `truncated` (paging of REST lists is not followed in v1). `az-read` entries are validated against the closed list but are not run as catalog checks in v1.
- **Retries.** 429, other 5xx and transient errors wait 1, 2, 4, 8, 16, then 30 seconds (total cap 180 seconds, so about nine retries); 403 and 400 are never retried; a timeout is retried once with the scope split per subscription. Part size limit: 1 MiB minus 8 KiB.
- **Redaction.** Tag values are hashed with the run id (`tag:` plus 8 hex digits) unless the key is `env`, `environment`, `tier`, `criticality`, `workload` or `costcenter`; an empty tag stays empty. A value in a declared scalar field that is an object or an array becomes `null` and is counted (`dropped` in the manifest), never stringified. Types the catalog may not read at all in v1 are listed in `scripts/lib/kql.mjs`; a check on them is refused. `run.json` keeps the subscription ids the collector queries with (also in strict mode); every other output file holds aliases.
- **Windows environment.** On Windows the child environment also keeps `SystemRoot`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `COMSPEC`, `PATHEXT`, `TEMP`, `TMP` and the Program Files variables (the `az` launcher needs them; not verified until M-10). `az --version` is the one vector that does not get `--only-show-errors`.
- **Catalog hash** is taken over the parsed JSON in canonical form, so a CRLF checkout hashes like an LF one. Doc dates are the checklist page dates read on 2026-11-25 (claim 15), not per recommendation.
- **CI.** A new job `azure-waf-review` (Ubuntu and Windows, Node 20 and 24, `npm test` in the folder, no install) was added to `validate.yml` because task 1.8 asks for Linux and Windows jobs; it is not a required check and no required context was renamed.
- **Not changed:** `assessment-report`, `docs-generator`, `azure-terraform-stacks`, the marketplace manifest, `package.json`, `docs/aep/context-budgets.json` (no `SKILL.md` was created, so nothing is measured), rulesets and `publish.yml`.
