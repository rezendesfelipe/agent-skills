- **Scope and `pass`.** The query scope is the readable subscriptions that are also under the management group. ### Corrections after the independent review of 41b0ff3 (the same pull request)

Red commit `b7e756d` (tests that reproduce each attack, failing on 41b0ff3), then the fixes below.

- **B-1, KQL validator.** `scripts/lib/kql.mjs` is now an allowlist. The text is reduced to ASCII and a closed set of characters by a literal-aware scanner; comments (`//`, `/*`), `;`, `@`, backticks and backslashes outside literals are refused, and the pipe splitter works on the blanked text, so a quote or a pipe inside a literal or a comment can no longer move the final `project`. What may be WRITTEN into the evidence is decided by `catalog/scalar-paths.json` (reviewed list of scalar paths and one derived expression) and by the `source` each output field declares: a projected column must be exactly `tostring|tobool|tolong(<source>)` of its declared source (a tag value `tags['key']` needs a `tagKey` field; `const:<text>` for a constant), `extend` expressions must be a conversion of a standard column, a listed path, a tag value, a constant or a listed derived expression, the violations query may not `summarize`, and object-building functions (`pack`, `bag_pack`, `todynamic`, `parse_json`, `make_*`) are refused anywhere. The catalog hash now includes `scalar-paths.json`. Limit: `where` may read any column, and the allowlist is only as good as the review of each path added to it.
- **I-1.** `join` accepts only `kind=` innerunique, inner, leftouter or fullouter, a parenthesized subquery that projects plain columns, and `on <column>` with the same name on both sides (the `$left`/`$right` form is not confirmed for Resource Graph and is refused). The three checks that used `leftanti` were rewritten (see 1.3); not run against Resource Graph.
- **B-2, `seal-check`.** Every entry of `collected/` must be `manifest.json`, `summary/<pillar>.md` or a part listed in the manifest as a regular file; a part name must be `<check>.NNN.jsonl` of its own check. Reproduced with the real `assess.mjs`: `verify` accepts a forged `collected/forged.jsonl`; `seal-check` now refuses it. Leftover `.tmp-*` folders are refused too.
- **B-3, `run.json`.** The manifest header holds a hash of the fields of `run.json` that change what a run means (run id, redaction, pillars, budget, catalog hash and the whole scope). `seal-check` and `collect` (resumed or not) compare it and refuse on a difference. In PR 1b the scope will come from `consent.json` (the user's typed count and the read list) and must be sealed into the manifest the same way; `runSha` in `scripts/lib/util.mjs` is the extension point.

Fixed: OE:06 (workload supply chain and pipelines), OE:09 (testing practices), OE:10 (reliable, secure automation) and several wordings. Mapping fixes after reading each recommendation: `SE-STG-002` is SE:07 primary (encryption in transit), `SE-DEF-001` is SE:10 primary, `RE-BKP-001` is only related to RE:09 (a backup item is not a disaster recovery plan), `CO-Q-001` is CO:03 primary (alerts at thresholds).
- **I-3.** `plan --redact strict` prints aliases and counts only (and `--json` the same). `run.json` still holds the real subscription ids the collector queries with.
- **I-4.** The `waf-review/` folder, run folders and every file are created `0700` and `0600` on POSIX. On Windows the ACL of the folder is **not** verified and the engine promises nothing about it.
- **I-5.** `isAllowedUrl` refuses `\`, `@`, `%`, `#`, spaces and control or non-ASCII characters before parsing (the `az rest` library parses URLs differently from WHATWG); a subscription id must be a GUID before it is placed in a URL.
